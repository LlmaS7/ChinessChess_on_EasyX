5.1 测试环境

操作系统：Windows 11 专业版 64 位
编译器：MinGW-w64 g++ 16.1.0（默认 C++20 标准）
图形库：EasyX 2023 大暑版
网络库：Winsock2 (ws2_32)
构建工具：VS Code + 自定义 tasks.json
硬件环境：Intel Core i5, 16GB RAM
网络环境：本地回环（127.0.0.1）+ 局域网（两台 PC 直连）
编译选项：-Wall -Wextra -g3 -static -finput-charset=utf-8 -fexec-charset=gbk -mwindows
链接库：EasyX（图形界面）、ws2_32（Winsock2 网络通信）、gdi32（GDI 绘图）、ole32（OLE 组件支持）、winmm（多媒体定时器）
字符编码：源码采用 UTF-8，编译时通过 -fexec-charset=gbk 将可执行程序中的字符串常量转换为 GBK，确保 EasyX 在 Windows 简体中文环境下正确显示汉字

测试方法：本地同时启动两个进程（主机 + 客机），通过回环地址模拟联机对战；同时使用单机模式覆盖全部规则功能。局域网测试通过两台 PC 直连验证。


5.2 测试用例

5.2.1 单机规则测试

S-01 棋盘初始化：启动程序，选择单机模式。预期：显示标准布局棋盘，红黑双方各 16 枚棋子，红方回合。通过。
S-02 选己方棋子：点击红方棋子（如俥）。预期：棋子高亮显示，棋盘显示该棋子合法走法（绿色圆点/红色圆圈）。通过。
S-03 取消选中：点击已选中的棋子。预期：高亮消失，回到选棋状态。通过。
S-04 切换选中：选中红炮后，点击红马。预期：红炮取消高亮，红马高亮并显示其合法走法。通过。
S-05 合法走棋：选中红炮，点击合法目标位置。预期：棋子移动成功，回合切换到黑方。通过。
S-06 选对方棋子：红方回合点击黑方棋子。预期：不选中，无响应。通过。
S-07 车直线移动：开局走红车前进 5 格。预期：走棋成功，中间无阻挡则合法。通过。
S-08 车被阻挡：有棋子位于车与目标之间时走车。预期：走棋失败。通过。
S-09 马走日：马跳日字到空位。预期：走棋成功。通过。
S-10 蹩马脚：马脚位置有子时走马。预期：走棋失败。通过。
S-11 炮翻山吃子：炮翻过一枚棋子吃掉目标。预期：走棋成功。通过。
S-12 炮无架吃子：炮与目标之间无棋子时尝试吃子。预期：走棋失败。通过。
S-13 炮移动不翻山：炮直线移动到空位（中间无子）。预期：走棋成功。通过。
S-14 象走田：象走田字且不过河。预期：走棋成功。通过。
S-15 堵塞象眼：象眼位置有子时走象。预期：走棋失败。通过。
S-16 象过河：象尝试走到过河位置。预期：走棋失败。通过。
S-17 士斜走一格：士在九宫内斜走一格。预期：走棋成功。通过。
S-18 士出九宫：士尝试走出九宫。预期：走棋失败。通过。
S-19 将直走一格：将在九宫内直走一格。预期：走棋成功。通过。
S-20 将出九宫：将尝试走出九宫。预期：走棋失败。通过。
S-21 防止对将：将与对方帅同列且中间无子时走将。预期：走棋失败。通过。
S-22 自将防御：走棋导致己方被将军。预期：走棋失败。通过。
S-23 卒未过河横走：未过河的卒尝试横向移动。预期：走棋失败。通过。
S-24 卒过河横走：过河的卒横向移动一格。预期：走棋成功。通过。
S-25 卒后退：卒尝试后退。预期：走棋失败。通过。
S-26 将军提示：走一步导致对方被将军。预期：对方九宫中心显示"将军"文字。通过。
S-27 将死判定：制造将死局面（如双車杀）。预期：游戏结束，本方获胜。通过。
S-28 单机悔棋：走一步后点击悔棋按钮。预期：棋子退回原位，回合回退。通过。
S-29 开局悔棋：开局时点击悔棋。预期：悔棋失败（history 为空），无变化。通过。
S-30 黑方认输：点击"黑方认输"按钮。预期：游戏结束，红方胜利。通过。
S-31 红方认输：点击"红方认输"按钮。预期：游戏结束，黑方胜利。通过。
S-32 走法提示显示：选中棋子后查看棋盘。预期：可走空位显示绿色圆点，可吃子位显示红色圆圈。通过。


5.2.2 联机功能测试

N-01 主机创建：选择"联机模式" → "创建主机"。预期：显示本机 IP，等待客机连接。通过。
N-02 客机连接：选择"联机模式" → "连接主机" → 输入 IP。预期：连接成功，进入游戏画面。通过。
N-03 连接失败处理：客机输入不存在的 IP。预期：显示"连接失败"，程序退出。通过。
N-04 走棋同步：主机走棋。预期：客机棋盘同步更新，回合切换到客机。通过。
N-05 回合锁定（对方）：对方回合时点击棋盘。预期：无响应，不能操作对方棋子。通过。
N-06 UI 按钮不受锁定：对方回合时点击认输按钮。预期：认输按钮正常响应。通过。
N-07 悔棋请求：己方点击悔棋。预期：对方显示"同意/拒绝"弹窗，己方棋盘锁定。通过。
N-08 同意悔棋：收到悔棋请求后点击"同意"。预期：双方各退相应步数，回到请求方回合。通过。
N-09 拒绝悔棋：收到悔棋请求后点击"拒绝"。预期：双方状态恢复，游戏继续。通过。
N-10 悔棋锁定：悔棋等待对方响应时点击棋盘。预期：无响应，棋盘被锁定。通过。
N-11 联机认输：己方点击认输按钮。预期：己方判负，对方收到 NET_RESIGN 判胜。通过。
N-12 一方正常关闭：一方关闭窗口。预期：另一方收到 FIN，检测断连后判获胜。通过。
N-13 一方强制结束：任务管理器强制结束一方进程。预期：另一方收到 RST，检测断连后判获胜。通过。

说明：N-13 是开发后期发现并修复的缺陷。最初 net_recv_msg() 仅处理 recv() == 0（FIN 优雅关闭），未处理 SOCKET_ERROR（RST 强制断连），导致一方强制结束后另一方无响应。修复方案：recv() 任何失败均标记 g_net.connected = false。


5.2.3 边界与稳定性测试

B-01 棋盘边缘走棋：在棋盘四角处选棋并走棋。预期：越界坐标被拒绝，走棋失败。通过。
B-02 单机关闭窗口：游戏过程中点击关闭按钮。预期：程序正常退出。通过。
B-03 联机关闭窗口：联机游戏中点击关闭按钮。预期：发送 GAME_OVER → 清理网络 → 退出。通过。
B-04 快速连续点击：快速连续多次点击棋盘和按钮。预期：每次点击独立处理，不产生死锁或崩溃。通过。
B-05 将死检测：测试双車杀、马后炮等经典将死局面。预期：check_over() 正确返回胜方颜色。通过。
