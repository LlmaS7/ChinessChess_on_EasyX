## 一、引言

中国象棋是中国最古老、最具代表性的棋类运动之一，有着广泛的群众基础。随着计算机技术的普及，在计算机上实现中国象棋对战已成为经典的程序设计课题。本程序基于 Windows 平台，使用 C/C++ 语言和 EasyX 图形库，实现了一款具备完整规则判定、图形化交互界面以及可选局域网联机对战功能的中国象棋对战程序。

本程序的设计目标不仅仅是完成一个"能走棋"的玩具程序，而是追求以下三个层次：

1. **规则完备性**：正确实现中国象棋全部棋子的走法规则、蹩马脚/堵象眼/炮翻山等特殊约束、将军与飞将判定、将死检测等核心逻辑。
2. **交互体验**：提供自然直观的鼠标选棋与走棋操作、合法走法提示、悔棋与认输功能、清晰美观的棋盘渲染。
3. **联机对战**：基于 TCP 协议实现局域网双人对战，支持走棋同步、悔棋请求/同意/拒绝协议、以及断线处理。

通过本程序的开发，可以综合运用数据结构（棋盘建模、走法历史栈）、算法（穷举合法走法、将军判定）、图形编程（EasyX 双缓冲渲染、鼠标事件处理）以及网络编程（Winsock2 套接字通信、自定义应用层协议）等多方面知识，具有较强的学习与实践意义。

## 二、需求分析

### 2.1 功能需求

#### 2.1.1 单机双人对弈

- 棋盘初始化：按中国象棋标准布局摆放红黑双方共 32 枚棋子。
- 走棋操作：玩家用鼠标点击己方棋子选中，再次点击目标位置完成走棋；点击同色棋子切换选中，点击空白或非法位置取消选中。
- 规则判定：严格按照中国象棋规则校验每一步走法是否合法，
- 自将防御：任何走法执行后若导致己方被将军，则该走法被判定为非法。
- 将军提示：被将军方九宫中心显示"将军"文字。
- 合法走法提示：选中棋子后，在棋盘上以绿色圆点（可走空位）和红色圆圈（可吃子位）高亮显示该棋子的所有合法走法。
- 将死判定：当某方所有棋子均无合法走法时，判定该方输棋，对方获胜。
- 悔棋：单机模式下可撤销上一步走法，恢复棋盘状态。
- 认输：红方或黑方可主动认输，对方获胜。

#### 2.1.2 联机双人对弈

- 角色分配：主机执红（先手），客机执黑（后手）。
- 连接建立：主机在指定端口监听，等待客机连接；客机输入主机 IP 地址发起连接。
- 走棋同步：本地走棋成功后，自动将走法数据通过网络发送给对方，对方自动执行相同走法。
- 回合锁定：仅当前回合方的玩家可以操作棋盘，另一方的鼠标点击被忽略（UI 按钮除外）。
- 悔棋协议：
  - 任意一方点击悔棋按钮后，向对方发送悔棋请求。
  - 对方同意 → 双方各回退相应步数，回到请求方回合。
  - 对方拒绝 → 撤销请求，游戏继续。
  - 在等待对方响应期间，本地棋盘操作被锁定。
- 认输同步：一方认输后，自动通知对方游戏结束。
- 断线处理：检测到对方断开连接时，本方自动获胜。

### 2.2 性能需求

- **渲染性能**：采用双缓冲机制，避免画面闪烁，确保流畅体验。
- **网络延迟**：局域网环境下，走棋数据包 < 40 字节，延迟应在 10ms 以内。
- **内存占用**：棋盘状态仅为一个 10×9 的二维数组，历史记录最多存储一局棋谱，内存占用应 < 10MB。

### 3.2 详细设计

#### 3.2.1 `chess_def.h` — 基础定义

本模块不包含函数，仅提供全项目共享的枚举、结构体和常量。

| 定义 | 说明 |
|------|------|
| `enum Piece` | 棋子类型：`SPACE=-1`，黑方 0-6（車馬象士将砲卒），红方 7-13（俥马相仕帥炮兵）。红黑双方索引偏移 7 |
| `enum Color` | `_NONE=-1, _RED, _BLACK`（前缀 `_` 避免与 EasyX 宏 `RED`/`BLACK` 冲突） |
| `enum Phase` | `SELECT_FIRST`（等待选棋）、`SELECT_SECOND`（等待走棋） |
| `struct Move` | 走法记录：`from_x/y, to_x/y, moved_id/color, captured_id/color` |
| 坐标转换 | `inline toX(col)` / `toY(row)` 将逻辑坐标转为像素坐标 |
| UI 常量 | `BOARD_LEFT/TOP`（棋盘偏移）、`CELL_SIZE`（60px）、`UI_BTN_X` 等布局参数 |

#### 3.2.2 `game_state.h` — 游戏状态

```cpp
struct ChessPiece {
    int id;    // Piece 枚举值
    int color; // Color 枚举值
};

struct GameState {
    ChessPiece board[10][9];    // 棋盘：10行 × 9列
    int current_side;            // 当前回合方 (_RED / _BLACK)
    int turn_count;              // 回合计数
    int phase;                   // 当前阶段 (SELECT_FIRST / SELECT_SECOND)
    int selected_x, selected_y;  // 当前选中棋子坐标 (-1 表示未选中)
    bool game_over;              // 游戏是否结束
    int winner;                  // 胜方颜色 (-1 表示未结束)
    vector<Move> history;         // 走法历史栈（悔棋用）
    bool undo_req_pending;       // 联机：对方请求悔棋等待响应中
};
```

#### 3.2.3 `chess_engine.h/cpp` — 象棋引擎（核心模块）

| 函数 | 功能 | 入口参数 | 返回值 | 调用关系 |
|------|------|---------|--------|---------|
| `init_game(state)` | 初始化棋盘 32 枚棋子与游戏状态 | `GameState &state` | `void` | — |
| `apply_move(state, fx, fy, tx, ty)` | 校验并执行走棋：7 类棋子规则 → 自将检查 → 更新棋盘 → 记录 history | `state, 起点(fx,fy), 终点(tx,ty)` | `bool` | 内部调用 `is_in_check()` |
| `undo_move(state)` | 撤销上一步走棋，恢复棋盘 | `GameState &state` | `bool`（history 空时返回 false） | — |
| `undo_to_turn(state, target_color)` | 联机悔棋：回退到指定颜色方的回合（退 1 或 2 步） | `state, target_color` | `void` | 内部调用 `undo_move()` |
| `is_attacked(state, x, y, attacker_color)` | 判断 `attacker_color` 方是否有棋子能攻击到点 `(x,y)`（不含飞将） | `state, 目标坐标, 攻击方颜色` | `bool` | — |
| `is_in_check(state, color)` | 判断 `color` 方是否正被将军（普通攻击 + 飞将检查） | `state, 被检查方颜色` | `bool` | 内部调用 `is_attacked()` |
| `get_legal_moves(state, fx, fy)` | 枚举 `(fx,fy)` 处棋子的所有合法走法 | `state, 棋子坐标` | `vector<Move>` | 遍历 90 个目标点，对每个调 `apply_move()` → `undo_move()` |
| `check_over(state)` | 将死判定：当前方所有棋子均无合法走法则判负 | `GameState &state` | `int`（胜方颜色，-1 未结束） | 内部遍历全盘调 `get_legal_moves()` |

**函数调用关系图：**

```
check_over()
  └── get_legal_moves()        ← 遍历所有棋子，对每个目标点：
        └── apply_move()       ← 校验走法合法性：
              └── is_in_check() ← 走后是否自将
                    └── is_attacked() ← 对方棋子能否攻击将/帥

mouse_input / game_control
  └── apply_move() / undo_move() / undo_to_turn()

draw_board()
  └── get_legal_moves()        ← 显示走法提示
  └── is_in_check()             ← 显示"将军"提示
```

**关键算法说明：**

1. **走棋合法性校验（`apply_move`）**：采用"规则校验 → 模拟执行 → 自将检查 → 正式提交"四步流程。模拟执行时暂存起终点旧值，若自将则恢复后返回 false，否则覆盖写入。

2. **合法走法枚举（`get_legal_moves`）**：对 10×9=90 个棋盘位置逐一调用 `apply_move()` 试探，若成功则立即 `undo_move()` 恢复并在结果集中记录该走法。注意 `apply_move()` 内部已完成自将检查，外层 **不能** 再次调用 `is_in_check()`，否则会产生双重判定导致错误。

3. **将死判定（`check_over`）**：遍历当前回合方所有棋子，对每个棋子调用 `get_legal_moves()`。若所有棋子返回的合法走法列表均为空，则当前方被将死，判对方获胜。由于被将军时不符合规则的走法也会被 `apply_move` 否定，无子可动即意味着被将死。

**状态转换流程：**

```

  │ 点击己方棋子 → 选中，进入 SELECT_SECOND
  │ 点击空处/对方棋子 → 忽略
  └──────────────────────────────────────┘

SELECT_SECOND (走棋)
  │ 点击同一棋子 → 取消选中，回到 SELECT_FIRST
  │ 点击己方其他棋子 → 切换选中，保持 SELECT_SECOND
  │ 点击目标位置 → apply_move() 校验，成功则输出 Move 并回到 SELECT_FIRST
  │               失败则取消选中，回到 SELECT_FIRST
  └──────────────────────────────────────┘
```

#### 3.2.8 `network.h/cpp` — 网络通信

| 函数 | 功能 | 入口参数 | 返回值 |
|------|------|---------|--------|
| `net_init()` | 初始化 Winsock2 | — | `bool` |
| `net_cleanup()` | 断开连接并清理 Winsock2 | — | `void` |
| `net_host(port)` | 创建 TCP 服务器，监听端口，阻塞等待客户端连接 | `port`（默认 8888） | `bool` |
| `net_connect(ip, port)` | 作为客户端连接指定 IP 的主机 | `ip, port` | `bool` |
| `net_disconnect()` | 关闭所有套接字，重置状态 | — | `void` |
| `net_send_msg(msg)` | 发送一条网络消息（先发 8B 包头，再发负载） | `const NetMessage &msg` | `bool` |

| `net_pack_move()` / `net_unpack_move()` | Move 结构体与字节流的互转 | `msg, move` | `void` |
| `net_get_state()` | 获取网络状态（只读） | — | `const NetState&` |
| `net_set_waiting_undo(bool)` | 设置悔棋等待状态 | `bool` | `void` |
| `net_get_local_ip()` | 获取本机 IPv4 地址字符串 | — | `const char*` |
| `net_role_str()` / `net_msg_type_str()` | 枚举值→可读字符串 | 对应枚举 | `const char*` |

| 枚举 | 含义 | 方向 | data_len | data 内容 |

| `NET_UNDO_REQ` | 悔棋请求 | 双向 | 0 | 空 |
| `NET_UNDO_ACCEPT` | 同意悔棋 | 双向 | 0 | 空 |
| `NET_UNDO_REJECT` | 拒绝悔棋 | 双向 | 0 | 空 |
| `NET_RESIGN` | 认输 | 双向 | 0 | 空 |
| `NET_GAME_OVER` | 游戏结束 | 双向 | 4 | `int winner` |
| `NET_DISCONNECT` | 断开连接 | 双向 | 0 | 空 |
