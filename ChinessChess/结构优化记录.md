## 问题 1：`net_get_state()` 返回可变引用破坏封装

### 原先写法

**network.h（第 88 行）：**
```cpp
NetState& net_get_state();   // 返回可变引用，外部可随意修改
```

**network.cpp（末尾）：**
```cpp
NetState& net_get_state()
{
    return g_net;
}
```

**外部直接写入（main.cpp / game_control.cpp）：**
```cpp
net_get_state().waiting_undo = false;   // main.cpp
net_get_state().waiting_undo = true;    // game_control.cpp
```

### 问题所在

`NetState` 包含三个字段：`role`、`connected`、`waiting_undo`。`net_get_state()` 返回了可变引用，意味着任何 include 了 `network.h` 的文件都可以随意改写这三个字段。

- `role` 和 `connected` 本应由 `net_host()` / `net_connect()` / `net_disconnect()` 独占写入
- 实际上只有 `waiting_undo` 被外部写入，但 API 设计上开了三扇门

**违反原则**：封装。网络模块的内部状态应受保护，外部应通过受控的 API 修改。

### 改正方案

1. `net_get_state()` 返回类型改为 `const NetState&`（只读）
2. 新增 `net_set_waiting_undo(bool)` 函数作为唯一写入口
3. 外部直接 `= false` / `= true` 替换为 setter 调用

### 修改内容

| 文件 | 改动 |
|------|------|
| `network.h` | `NetState&` → `const NetState&`；新增 `void net_set_waiting_undo(bool waiting);` |
| `network.cpp` | `NetState&` → `const NetState&`；追加 setter 实现（4 行） |
| `main.cpp` | `net_get_state().waiting_undo = false` → `net_set_waiting_undo(false)`（2 处） |
| `game_control.cpp` | `net_get_state().waiting_undo = true` → `net_set_waiting_undo(true)`（1 处） |

## 问题 2：全局变量 `g_undo_req_pending` 放错位置

### 原先写法

**network.h（第 22 行）：**
```cpp
extern bool g_undo_req_pending;   // 全局标志：对方请求悔棋
```

**network.cpp（第 11 行）：**
```cpp
bool g_undo_req_pending = false;
```

**使用处（共 6 处）：**
- `main.cpp`：网络消息回调中赋值（3 处）
- `game_control.cpp`：同意/拒绝按钮点击后赋值（2 处）
- `draw_board.cpp`：读取以决定是否画悔棋弹窗（1 处）
- `network.cpp`：断开连接时清零（1 处）

### 问题所在

`g_undo_req_pending` 是一个**游戏 UI 状态**——表示"对方请求悔棋，等待本地玩家点击同意/拒绝"。它：

1. **不需要存在于网络层**：网络层只管收发消息，不管 UI 是否在显示弹窗
2. **是全局变量**：任何文件都可以随意修改，没有归属感
3. **网络层断开时还要清除它**：`network.cpp` 的 `net_disconnect()` 需要额外处理这个不归它管的状态

**语义归属**：这是**游戏流程中的 UI 等待状态**，和 `current_side`、`phase` 等属性一样属于 `GameState`。

### 改正方案

将 `undo_req_pending` 移入 `GameState` 结构体，删除全局变量。所有引用改为 `state.undo_req_pending`。

### 修改内容

| 文件 | 改动 |
|------|------|
| `game_state.h` | `GameState` 新增 `bool undo_req_pending;` |
| `chess_engine.cpp` | `init_game()` 中初始化 `state.undo_req_pending = false;` |
| `network.h` | 删除 `extern bool g_undo_req_pending;` |
| `network.cpp` | 删除 `bool g_undo_req_pending = false;`；`net_disconnect()` 中删除清零行 |
| `main.cpp` | `g_undo_req_pending` → `state.undo_req_pending`（3 处） |
| `game_control.cpp` | `g_undo_req_pending` → `state.undo_req_pending`（3 处） |
| `draw_board.cpp` | `g_undo_req_pending` → `state.undo_req_pending`（1 处） |

## 问题 3：悔棋回退逻辑重复

### 原先写法

**main.cpp（NET_UNDO_ACCEPT 消息处理）：**
```cpp
// 对方同意悔棋 → 本地也执行悔棋
int my_color = (menu_choice == MENU_HOST) ? _RED : _BLACK;
if (state.current_side == my_color)
{
    undo_move(state);
    undo_move(state);
}
else
{
    undo_move(state);
}
```

**game_control.cpp（同意按钮处理）：**
```cpp
// 请求方是对方，如果当前是对方回合→退2步；否则退1步
int opp_color = (net_role == ROLE_HOST) ? _BLACK : _RED;
if (state.current_side == opp_color)
{
    undo_move(state);
    undo_move(state);
}
else
{
    undo_move(state);
}
```

### 问题所在

两段代码逻辑完全一致：**如果当前回合方是请求方，说明只走出了一步（对方还没走），退 1 步；否则退 2 步回到请求方回合**。但代码被复制粘贴，且变量名不同（`my_color` vs `opp_color`），容易在后续维护中遗漏其中一处。

**违反原则**：DRY（Don't Repeat Yourself）。

### 改正方案

在 `chess_engine.h/cpp` 中新增 `undo_to_turn()` 函数，封装回退逻辑：

```cpp
void undo_to_turn(GameState &state, int target_color)
{
    if (state.current_side == target_color)
        undo_move(state);      // 请求方回合已到，只退 1 步
    else
    {
        undo_move(state);
        undo_move(state);       // 退 2 步回到请求方
    }
}
```

两处调用简化为一行：`undo_to_turn(state, color);`

### 修改内容

| 文件 | 改动 |
|------|------|
| `chess_engine.h` | 新增 `void undo_to_turn(GameState &state, int target_color);` |
| `chess_engine.cpp` | 新增 9 行实现 |
| `main.cpp` | `NET_UNDO_ACCEPT` 分支 8 行 → 1 行 `undo_to_turn(state, my_color);` |
| `game_control.cpp` | 同意按钮 12 行 → 3 行（计算 opp_color + 调用） |

## 问题 4：菜单逻辑混杂在 `draw_board.cpp`

### 原先写法

`draw_board.cpp` 包含 ~150 行菜单代码：
- `show_start_menu()` — 主菜单 + 联机子菜单
- `get_connect_ip()` — IP 缓冲区
- `draw_btn()`、`in_btn()`、`wait_click()` — 辅助函数
- `static char g_connect_ip[16]` — 静态 IP 缓冲区

同时 `draw_board.h` 中混入了菜单相关声明和宏定义：
```cpp
#define MENU_SINGLE 1
#define MENU_HOST   2
#define MENU_CLIENT 3
int show_start_menu();
const char* get_connect_ip();
```

### 问题所在

`draw_board.cpp` 的职责是**渲染棋盘和 UI**，菜单逻辑（开始界面、IP 输入、按钮交互）是**完全不同的职责**。

- `main.cpp` 为了拿到 `MENU_SINGLE/2/3` 常量，不得不 `#include "draw_board.h"`
- 菜单函数和绘制函数混在一个文件里，维护者难以定位
- `draw_board.cpp` 包含了 `<graphics.h>` 用于画棋盘，菜单也用同一个 include，但本质不同

**违反原则**：单一职责原则（SRP）。

### 改正方案

新建 `menu.h` 和 `menu.cpp`，把菜单相关的所有内容搬迁过去：
- 宏定义 `MENU_SINGLE/2/3`
- `show_start_menu()`
- `get_connect_ip()` 及 `g_connect_ip`
- 三个辅助函数 `draw_btn/in_btn/wait_click`

`draw_board.h` 和 `draw_board.cpp` 删除对应内容。

### 修改内容

| 操作 | 文件 | 说明 |
|------|------|------|
| **新建** | `include/menu.h` | 菜单声明 + 宏定义 |
| **新建** | `src/menu.cpp` | 菜单实现（~120 行） |
| 修改 | `draw_board.h` | 删除菜单声明和宏定义（5 行） |
| 修改 | `draw_board.cpp` | 删除菜单实现（~150 行） |
| 修改 | `main.cpp` | `#include "../include/draw_board.h"` → 加 `#include "../include/menu.h"` |
| 修改 | `tasks.json` | 编译列表加 `menu.cpp` |

## 问题 5：UI 层直接依赖网络层读取状态

### 原先写法

**draw_board.cpp 头部：**
```cpp
#include "../include/draw_board.h"
#include "../include/chess_engine.h"
#include "../network/network.h"    // ← UI 层直接引用网络层
#include <graphics.h>
```

**draw_board.cpp 函数体内：**
```cpp
void draw_board(GameState &state)
{
    // ...
    NetRole net_role = net_get_state().role;           // 读网络角色
    bool is_network = (net_role == ROLE_HOST || net_role == ROLE_CLIENT);
    // 根据 net_role 决定按钮布局
    if (net_role == ROLE_CLIENT) { /* ... */ }
    // ...
    if (g_undo_req_pending) { /* 画悔棋弹窗 */ }
}
```

**game_control.cpp 同样：**
```cpp
#include "../network/network.h"

bool handle_control_click(GameState &state, int px, int py)
{
    NetRole net_role = net_get_state().role;
    bool is_network = (net_role == ROLE_HOST || net_role == ROLE_CLIENT);
    // 根据 net_role 决定点击响应逻辑
}
```

### 问题所在

绘制层和 UI 控制层通过 `net_get_state().role` 来感知"是否联机"和"是红方还是黑方"。

1. **依赖方向不对**：UI 层属于上层，网络层属于底层。上层的绘制代码不应该知道 `NetRole` 枚举、`ROLE_HOST/CLIENT` 这些网络概念
2. **信息传递路径迂回**：`main.cpp` 已经知道 `menu_choice`（MENU_HOST/CLIENT），完全可以直接告诉 UI 层需要什么信息，而不是让 UI 层自己去问网络层
3. **耦合度增加**：如果将来网络 API 改名，UI 代码也得跟着改

**"解耦"并不意味着 UI 层完全不接触 network.h**——UI 层仍然需要调用 `net_send_*()` 来**发送**悔棋请求、认输等消息。这是合理的，因为发送是"动作"，不读取网络内部状态。

### 改正方案

改为**参数传递**模式：
- `draw_board()` 加 `bool is_network, bool is_host` 参数
- `handle_control_click()` 加相同参数
- `main.cpp` 在主循环外计算好 `is_network` / `is_host`，传入各函数
- `draw_board.cpp` 删除 `#include "../network/network.h"`
- `game_control.cpp` 保留 `network.h`（因为要调 `net_send_*()`），但不再调 `net_get_state()`

### 修改内容

| 文件 | 改动 |
|------|------|
| `draw_board.h` | `draw_board(state)` → `draw_board(state, is_network, is_host)` |
| `draw_board.cpp` | 删除 `#include "../network/network.h"`；删除 `net_get_state()` 调用；用参数 `is_network`/`is_host` 替代 |
| `game_control.h` | `handle_control_click(state, px, py)` → `handle_control_click(state, px, py, is_network, is_host)` |
| `game_control.cpp` | 删除 `net_get_state().role` 读行；参数 `is_host` 替代 `net_role == ROLE_HOST` |
| `main.cpp` | 新增 `bool is_network = ...; bool is_host = ...;`；所有调用处传入新参数 |

### 架构对比

```
优化前：
  main.cpp ──include──▶ network.h
  draw_board.cpp ──include──▶ network.h (读取 g_net.role)
  game_control.cpp ──include──▶ network.h (读取/写入 g_net)

优化后：
  main.cpp ──include──▶ network.h (唯一读取 network 内部状态的地方)
       │                   │
       │ is_network/is_host│
       ▼                   ▼
  draw_board.cpp      game_control.cpp
                    ──include──▶ network.h (仅调用 net_send_*() 发送消息)
```

## 问题 6：`main.cpp` 主循环臃肿

### 原先写法

主循环中有一段 ~50 行的网络消息处理代码（嵌套在一个 `if (is_network_game(menu_choice))` 内），包含 7 种消息类型的 `if-else` 分支：

```cpp
if (is_network_game(menu_choice))
{
    NetMessage msg;
    if (net_recv_msg_nonblock(msg))
    {
        if (msg.type == NET_MOVE)
        {
            if (!is_my_turn(...))
            {
                Move move;
                net_unpack_move(msg, move);
                apply_move(...);
                check_over(state);
            }
        }
        else if (msg.type == NET_UNDO_REQ)
        {
            printf("[main] 对方请求悔棋\n");
            state.undo_req_pending = true;
        }
        else if (msg.type == NET_UNDO_ACCEPT)
        {
            // 8 行悔棋回退逻辑
        }
        else if (msg.type == NET_UNDO_REJECT)
        {
            // 3 行
        }
        else if (msg.type == NET_RESIGN)
        {
            // 3 行
        }
        else if (msg.type == NET_DISCONNECT)
        {
            // 3 行
        }
    }
}
```

### 问题所在

主循环 `while (!state.game_over)` 中混杂了：
1. 鼠标事件处理
2. 网络消息分发
3. 窗口关闭检测
4. 渲染

而消息分发是一个独立的子任务，40 多行代码打断了主循环的阅读节奏。

### 改正方案

提取为独立函数 `process_network_msg()`，用 `switch-case` 代替 `if-else` 链：

```cpp
static bool process_network_msg(GameState &state, int menu_choice)
{
    NetMessage msg;
    if (!net_recv_msg_nonblock(msg))
        return false;

    switch (msg.type)
    {
    case NET_MOVE:        /* 5 行 */ break;
    case NET_UNDO_REQ:    /* 1 行 */ break;
    case NET_UNDO_ACCEPT: /* 5 行 */ break;
    case NET_UNDO_REJECT: /* 3 行 */ break;
    case NET_RESIGN:      /* 2 行 */ break;
    case NET_DISCONNECT:  /* 2 行 */ break;
    }
    return true;
}
```

主循环中的调用简化为：
```cpp
if (is_network)
    process_network_msg(state, menu_choice);
```

### 修改内容

| 文件 | 改动 |
|------|------|
| `main.cpp` | 在 `main()` 之前新增 `process_network_msg()` 函数（~40 行）；主循环中 ~50 行替换为 2 行调用 |

## 问题 7：`main()` 函数中网络初始化和结算逻辑过长

### 原先写法

`main()` 中网络初始化占 ~50 行，结算退出占 ~20 行：

```cpp
int main()
{
    int menu_choice = show_start_menu();

    //  网络初始化（~50 行）
    if (menu_choice == MENU_HOST)
    {
        if (!net_init()) { ... return 0; }
        // 显示 IP、等待连接、net_host、closegraph、检查 connected ...
    }
    else if (menu_choice == MENU_CLIENT)
    {
        if (!net_init()) { ... return 0; }
        // show_wait_window、get_connect_ip、net_connect、检查 ...
    }

    // ... 游戏循环 ...

    // 结算（~20 行）
    if (is_network) net_send_game_over(state.winner);
    draw_board(state, ...);
    Sleep(500);
    show_result(state);
    // 等按键
    ExMessage em; while (true) { ... }
    if (is_network) net_cleanup();
    closegraph();
    return 0;
}
```

### 问题所在

`main()` 中既有"怎么启动网络"的实现细节（initgraph、sprintf、setbkcolor……），又有"怎么结算退出"的细节（Sleep、等按键、cleanup）。这些细节与 `main()` 的核心职责——"编排流程"——无关。读者看 `main()` 时应该一眼看到整体流程，而不是被琐碎的初始化/清理代码打断。

### 改正方案

提取两个函数：

**`net_startup(menu_choice)`** — 封装网络初始化的全部细节：
```cpp
static bool net_startup(int menu_choice)
{
    if (!net_init()) return false;
    if (menu_choice == MENU_HOST) { /* 显示IP + net_host */ }
    else                          { /* 连接主机 */ }
    if (!net_get_state().connected) { net_cleanup(); return false; }
    return true;
}
```

**`game_over_sequence(state, is_network, is_host)`** — 封装结算→清理的全部细节（不返回，直接 closegraph 退出）：
```cpp
static void game_over_sequence(GameState &state, bool is_network, bool is_host)
{
    if (is_network) net_send_game_over(state.winner);
    draw_board(...); Sleep(500); show_result(...);
    // 等按键
    if (is_network) net_cleanup();
    closegraph();
}
```

`main()` 简化为：
```cpp
int main()
{
    int menu_choice = show_start_menu();
    if (is_network_game(menu_choice) && !net_startup(menu_choice))
        return 0;

    initgraph(800, 640);
    GameState state; init_game(state);
    bool is_network = ...; bool is_host = ...;

    while (!state.game_over) { /* 30 行主循环 */ }

    game_over_sequence(state, is_network, is_host);
    return 0;
}
```

### 修改内容

| 文件 | 改动 |
|------|------|
| `main.cpp` | 新增 `net_startup()`（~40 行）和 `game_over_sequence()`（~20 行）；`main()` 中 ~70 行替换为 2 行调用 |

### 效果

`main()` 从 ~140 行精简到 **~85 行**，结构一目了然：选菜单 → 启动网络 → 初始化 → 游戏循环 → 结算退出。
